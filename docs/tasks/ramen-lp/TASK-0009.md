## 実装詳細

### 1. Intersection Observerスクリプトの作成 🔵

**信頼性**: 🔵 *REQ-301に基づくスクロールアニメーション実装*

- `[data-animate]`属性を持つ全要素をIntersection Observer APIで監視する
- 要素がビューポートに入った時点で`is-visible`クラスを付与する
- Observer設定: `threshold: 0.1`（要素の10%が見えた時点でトリガー）
- 一度表示された要素は`unobserve`してパフォーマンスを確保する

### 2. アニメーションタイプのCSS定義 🔵

**信頼性**: 🔵 *REQ-301で定義されたアニメーション種別*

以下のアニメーションタイプを`data-animate`属性値として対応する:

- `fade-in-up` — 下から上へフェードイン（opacity:0 + translateY(30px) → 初期状態）
- `slide-in-left` — 左からスライドイン（opacity:0 + translateX(-50px) → 初期状態）
- `slide-in-right` — 右からスライドイン（opacity:0 + translateX(50px) → 初期状態）
- `scale-in` — 拡大フェードイン（opacity:0 + scale(0.9) → 初期状態）
- `line-draw` — 線描画アニメーション（SVGまたはborderのアニメーション）
- `text-reveal` — テキスト出現アニメーション（clip-pathまたはopacityベース）

各要素は初期状態で`opacity: 0`と`transform`を設定し、`.is-visible`クラス付与時に`transition`でアニメーションさせる。

### 3. パララックス効果の実装 🔵

**信頼性**: 🔵 *REQ-301パララックス効果*

- Heroセクションの背景画像に対して`scroll`イベントリスナーを設定
- スクロール量に応じて`translateY`を適用（速度係数: 0.3〜0.5）
- `requestAnimationFrame`でパフォーマンスを最適化
- パララックスの計算: `translateY(scrollY * 0.4)`

### 4. ヘッダースクロール連動の最終調整 🔵

**信頼性**: 🔵 *REQ-012ヘッダーのスクロール連動*

- スクロール位置が100pxを超えた時点でヘッダーの背景を変更
- 背景変更: 透明 → `backdrop-blur` + 背景色（opacity付き）
- `scroll`イベントリスナーで監視（`passive: true`オプション）
- CSS変数`--header-bg-opacity`を動的に更新する方式

### 5. スムーズスクロールの設定 🔵

**信頼性**: 🔵 *REQ-103スムーズスクロール*

- HTMLルート要素に`scroll-behavior: smooth`を設定
- `scroll-padding-top: 5rem`で固定ヘッダー分のオフセットを確保
- 全てのナビゲーションアンカーリンク（`a[href^="#"]`）がスムーズにスクロール
- JavaScriptによるフォールバック不要（CSS native smooth scroll使用）

### 6. 3テーマバリエーションでの動作検証 🔵

**信頼性**: 🔵 *全バリエーションでの統合確認*

- `index.astro`（デフォルトテーマ）での全アニメーション動作確認
- `variant-dark.astro`（ダークテーマ）での全アニメーション動作確認
- `variant-light.astro`（ライトテーマ）での全アニメーション動作確認
- CSS変数によるテーマ切替がアニメーションに影響しないことを確認

## 単体テスト要件

- Intersection Observerスクリプトが`[data-animate]`要素を正しく検出すること
- `is-visible`クラスが要素のビューポート進入時に付与されること
- 各アニメーションタイプ（fade-in-up, slide-in-left等）のCSS初期状態が正しいこと
- `.is-visible`付与後のCSS遷移状態が正しいこと
- パララックスの`translateY`計算が正しいこと
- ヘッダー背景変更の閾値（100px）が正しく機能すること

## 統合テスト要件

- ページ全体をスクロールした際に全セクションが順次アニメーションすること
- パララックスとスクロールアニメーションが競合しないこと
- ヘッダーのスクロール連動とスムーズスクロールが同時に正常動作すること
- ナビリンクをクリックした際にスムーズスクロールで目的セクションに遷移すること
- 3テーマすべてで全インタラクションが一貫して動作すること

## UI/UX要件

### モバイル対応

- モバイルでもスクロールアニメーションが正常に動作すること
- タッチスクロールでの`Intersection Observer`の発火を確認
- モバイルでのパララックス効果がパフォーマンスに影響しないこと（必要に応じてモバイルでは無効化）

### アクセシビリティ

- `prefers-reduced-motion: reduce`メディアクエリに対応し、アニメーションを無効化すること
- アニメーション無効時でもコンテンツが正しく表示されること（opacity: 1, transform: none）
- スクロールアニメーションがスクリーンリーダーの動作に影響しないこと

## 注意事項

- `scroll`イベントリスナーには必ず`{ passive: true }`を指定してパフォーマンスを確保する
- `requestAnimationFrame`を使用してスクロール系処理のフレームレートを最適化する
- モバイルでのパララックスはバッテリー消費とパフォーマンスに影響するため、必要に応じて無効化を検討する
- `prefers-reduced-motion`対応は必須 — アニメーション無効時にコンテンツが非表示にならないよう注意
- Intersection Observerの`threshold`値は実際の見た目に合わせて微調整する可能性がある
- スクリプトは`<script>`タグ内でAstroのクライアントサイドスクリプトとして記述する
